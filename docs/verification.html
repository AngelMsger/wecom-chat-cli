Verification record

Version: 0.2.0-dev. Date: 2026-11-09. Toolchain: Go 1.27.3. All credentials and conversations in tests are synthetic.

Relay port verification (2026-11-12)

The Channel-derived relay passed GOWORK=off make lint test e2e build docs-check site-check release-tests, all three npm installer tests, and make vuln with Go 1.27.4 (no vulnerabilities found). Linux race tests and real CLI processes used normal filesystem ownership outside the executor's mapped-root sandbox; production ancestor checks remain unchanged. Linux/macOS amd64/arm64 cross-builds passed; these are not new native macOS runtime results.

The new real-process fixture covers a quiet baseline, duplicate callbacks, a lost HTTP response, restart and retry-reset refusal, evidence-based resolution, identical retry payloads, HTTP acceptance separated from completion, persistent consumer claims, duplicate claims without work or token, completion status and rejection of relay collection through the worker socket. Unit tests cover queue saturation, atomic persistence boundaries, malformed pages, unsafe paths/hard links, expired work, session/epoch separation, immutable attempted batches, pacing, retry budgets and terminal errors across restart in both delivery modes.

The network-disabled Linux isolation fixture also passed, with a worker unable to read sender configuration/state/key or supervisor claims, reach the operator socket or enumerate the watch feed. It retained only its single-event grant. No production Grok routine, WeCom bot or live message was used. Host scheduling, grant provisioning, reviewer behavior and real AI usage remain deployment checks; local claim dedupe does not prove zero duplicate paid wakeups.

Monitoring change verification (2026-11-10)

PR #4 performance follow-up: the original predicate benchmark for 100 pending events followed by 9,900 unrelated assigned events measured 1.01–1.50 s and about 602 MB allocated per iteration on this Linux amd64 environment. With a per-snapshot assignment index, the same benchmark (including index construction) measured 0.81–0.83 ms and 30,400 bytes allocated. These are predicate measurements excluding snapshot cloning and response encoding, not end-to-end latency or token savings. Run go test ./internal/broker -run '^$' -bench '^BenchmarkPendingDiscovery$' -benchmem to reproduce the fixture. Session/epoch tests preserve supersession by revoked, expired and completed tasks and separation across users/conversations.

A real CLI/Unix-socket regression failed on the old code when a filtered callback arrived during event watch --cursor ... --duration 1s: the terminal cursor stayed at its input value. The regression checks the returned cursor against an immediate broker read and confirms stdout stays empty. Millisecond server waits now leave a response budget before the outer deadline so filtered progress can return.

The pending-reference watch passed pinned-module make lint test e2e build docs-check site-check release-tests, the three npm installer tests and make vuln (no vulnerabilities found). Race and real CLI/socket tests used the existing network-disabled container runner because the cloud host maps root ancestors to an untrusted owner. Production filesystem checks were not weakened.

New cases cover a quiet baseline, explicit replay, metadata-only records, duplicate callback intake, watch/audit cursor separation, idle and filtered long polls, emitted-stage checkpoints and arrivals between bounded CLI processes. Closed-work cases include expired deadlines, old connection/session, blocked users, existing/revoked grants, drafts, reports, sent/uncertain outcomes, superseded events and reopened durable state. Busy sessions retain later work without bypassing issuance serialization; worker authority remains unchanged.

These checks prove local discovery/output behavior, not Grokbot's durable inbox, job submission, crash recovery or actual model-invocation counts. No live bot or host was activated. Earlier CI and OS-isolation results below describe their recorded commits; they are not fresh results for this change.

Managed-environment test runner

This task's outer filesystem exposes / and /tmp as owned by UID 65534. The broker intentionally rejects that environment instead of weakening its trusted ancestor checks. Filesystem tests therefore ran in a conventional Ubuntu root filesystem with networking disabled. The compiler ran outside the container; test executables ran inside it. A pinned image and a reusable runner are included:

# Prefetch public dependencies and the test image using the host's configured
# network/proxy/CA settings before starting the network-disabled tests.
go mod download
docker --host=unix:///var/run/docker.sock pull \
  ubuntu@sha256:fe81560990fae86dc4743202b2cb4d3df98d0bcf949173cecef15ce1127ef852

GOFLAGS="-exec=$PWD/scripts/container-exec.sh" make test e2e
WECOM_CHAT_TEST_ROOT=1 GOFLAGS="-exec=$PWD/scripts/container-exec.sh" make isolation-check

The ordinary test container runs as the current UID, with a read-only root, read-only source/module/toolchain mounts, no Linux capabilities and no network. An executable temporary filesystem supports the compiled CLI fixture. The OS isolation fixture mounts only its synthetic test executable; its root setup process receives CHOWN/SETUID/SETGID solely to construct distinct identities, and the worker has none. No Docker socket, host home or credential files are mounted.

Linux/macOS CI runs make lint test e2e build docs-check site-check release-tests and installer/vulnerability checks directly. The optional isolation test must use a disposable root setup environment and fails if invoked as an ordinary user; it never silently reports an unexecuted check as passed.

Not verified or delivered

  • A live WeCom tenant, actual Bot ID/Secret, enterprise rollout and server reply validity window; no live messages were sent and no bot configuration changed.
  • A concrete grok bot SDK/plugin adapter or the host's actual sandbox and tools.
  • Disconnected-message replay/backfill or exactly-once model execution.
  • General prompt-injection detection or factual-answer correctness; adversarial tests prove restricted effects, not semantic classification quality.
  • The trustworthiness of an external automated reviewer or its credentials.
  • Long-term ledger archival/compaction and high-volume durability/performance.
  • Production systemd installation, private WeCom deployments and Windows sockets.

Version 0.2.0 is available through GitHub Releases and npm. On 2026-11-10 its npm tarball integrity, Linux amd64 installation and reported release commit were verified. Its initial npm publication was manual; that does not establish OIDC publisher readiness for later releases.

CI and public Pages deployment are verified above; repository administration and live deployment remain separate acceptance items. The hard event cap and explicit coverage gaps must remain visible until a production retention/operations design is added.
